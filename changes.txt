Four follow-up fixes after stats started loading (all verified in field logs):
- Vore potions bag no longer double-fills: with stats loading, the bag template's own treasure
	table generates its contents, so the manual potion adds from the previous fix were removed.
- Dragonborn bellies: a CustomRacesBellies.json entry overriding the built-in Dragonborn race with
	nonexistent belly sets (Dragonborn3/Dragonborn4) aborted the visual update. SP_UpdateBelly now
	validates each candidate config and falls back to the built-in belly table when the referenced
	set doesn't exist.
- AddPassiveSafe false alarms removed: Osi.HasPassive does not reflect a passive on the tick it is
	added - verification is delayed by 3 ticks, and the broken PassiveContainer fallback (v32 rejects
	stats objects in that array) was removed since Osi.AddPassive works.
- The SP_CanXxxVore passives now also unlock the container child spells (Swallow Endo/Lethal
	variants) alongside the container itself, and drinking a potion logs the character's SP_ spellbook
	contents for diagnosing spell unlock issues.

ROOT CAUSE of the missing passives/spells found via Ext.Stats.Get diagnostics: the game's stats
	scanner does not recurse into subdirectories under Stats/Generated/Data/ - the mod kept its stats
	in Data/Items, Data/Passive, Data/Spells, Data/Status, Data/Subclasses (a recent upstream refactor),
	so NONE of them were ever loaded (verified against the game's own paks and 18 working mods, which
	all keep stats flat in Data/). The build now flattens Data/**/*.txt into Data/ at package time.
	Session load now also logs whether the key stats are present for quick verification.

Fixed SP_AddPassiveSafe itself aborting the potion handler: Ext.Stats.Get has no (type, name)
	two-string overload in SE v32 (argument #2 must be a number), so the diagnostic call threw and
	killed the whole SP_OnItemUsed handler before Osi.AddPassive ever ran. The stats lookup now uses
	the single stat-name form, is pcall-wrapped, and never prevents the Osi/UUID/PassiveContainer
	attempts below it from running.

Passive handling reworked after console logs showed Osi.AddPassive executing without errors
	but the passives never appearing (HasPassive=0 two ticks later). New helpers in OsiUtils.lua:
	SP_HasPassiveSafe (cross-checks the entity's PassiveContainer), SP_AddPassiveSafe (stats-existence
	diagnosis, bare-UUID retry, direct PassiveContainer fallback) and SP_RemovePassiveSafe. The potion
	path, pred status bookkeeping and SP_GetPredLoci now use them; every failure mode logs an [SP] line.

Fixed drinking a vore potion not unlocking the swallow spells: the character is now tagged as a
	predator (SP_IsPred) BEFORE the locus passive is added, and the SP_CanXxxVore passives unlock their
	spells unconditionally instead of under IF(Tagged('PREDATOR',context.Source)) - the spell unlock no
	longer depends on tag evaluation order or context semantics. SP_OnItemUsed logs every step ([SP]
	prefix) so failures are traceable in the Script Extender console.

Second attempt at the empty 'Bag of Vore Potions' fix: TemplateAddTo is asynchronous, so the bag
	is only looked up after a few ticks and the eight potions are added into it directly (the previous
	GenerateTreasure call silently did nothing because the bag lookup ran before the item existed).

Full Simplified Chinese localization of the mod's loca (539/539 entries: items, potions, spells,
	statuses, feats, subclasses, tooltips and popups) - previously only the MCM menu was translated.
Fixed the 'Bag of Vore Potions' spawning empty: the bag's root-template InventoryList does not
	generate its treasure table, so SP_GiveVoreItems now calls Osi.GenerateTreasure explicitly.
CI artifact now contains only DevouringAndDigesting.pak (the zip-wrapped copy remains the release
	asset format for v* tags).

Dragonborn belly VisualBank entries (DGB_F/M_NKD_Body_A_Mesh) now set NeedsSkeletonRemap=True so the engine remaps the
	old baked bone bindings against the current (Patch 8 reworked) DGB_F_Base skeleton by bone name - data-only fix attempt for issue #40;
	the definitive fix is re-exporting the belly GR2s against the current skeleton (Blender/remeshed.blend + Blender/main.py pipeline).
Added GitHub Actions build (build-mod.yml + Scripts/build-mod.ps1): converts loca.xml/lsf.lsx with lslib divine and packs the mod
	into DevouringAndDigesting.pak wrapped in a zip for BG3 Mod Manager import; verified locally.

VoreData is now persisted via ModVariables (ModVoreData) instead of the deprecated BG3SE PersistentVars table (issue #46).
	A one-time migration runs on session load for savegames created before this change; the deprecation warning on BG3SE v31+ should be gone.
	VoreData mutations are re-dirtied for savegame persistence on a periodic tick (subproperty writes do not mark ModVars dirty).
SwallowCheck (Scripts/thoth/helpers/conditions.khn) is wrapped in try/catch with a plain Athletics-DC10 fallback roll, so a failing
	evaluation no longer consumes the action without a roll (issue #42). Prey Evasion is now checked on the prey instead of the predator,
	GetPassiveSkill results are nil-guarded, and Dead() was added to the willing check (matching the game's ShoveCheck).
Added a Simplified Chinese localization overlay (Localization/Chinese) covering the whole MCM blueprint: tab names, all setting
	names/descriptions, radio choice labels, and the mod display name. MCM_blueprint.json tabs now carry NameHandles and the three
	radio settings carry ChoicesHandles (values are unchanged, only labels are localized).

Vore spells now have a strict naming convention. The convention is "SP_" + SpellType + "_" + the effect of the spell (Swallow_Endo, Swallow_Lethal, Bellyport, etc) + "_" + the first letter of the voreType.
	An example would be "SP_Target_Swallow_Lethal_O". This change was made to allow us to pattern match the spells, which is way cleaner then grabbing substrings
