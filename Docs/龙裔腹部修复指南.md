# 龙裔腹部修复指南（保姆级）

> 目标：让龙裔（Dragonborn）角色吞噬后腹部正确变大。
> 适用版本：游戏 Patch 8（v4.73.x），mod 仓库本地检出。
> 预计工作量：方案 A 约 1–3 小时（大部分是等待批量脚本跑完）；无需美术功底。

---

## 0. 为什么龙裔腹部坏了（30 秒版）

游戏内日志已经证明**代码链路完全正常**：

```
Devouring | Updating belly visual; Race: Dragonborn Sex: Male Belly: 8b7767e9-...
Devouring | Visuals after override: 7f172a17-..., ..., 8b7767e9-...   ← 腹部 UUID 已写入角色
```

腹部的视觉资源被正确挂到了角色身上，但**网格渲染不出来**。原因：

- 本 mod 的 100 个龙裔腹部网格（`SP_DGB_F_Belly_1..50.GR2`、`SP_DGB_M_Belly_1..50.GR2`）
  是在旧版（4.0.9 时代）的龙裔骨架上烘焙蒙皮的；
- 官方 Patch 8 重做了龙裔资产，`DGB_F_Base` / `DGB_M_Base` 骨架用新版编辑器重新导出过
  （骨骼增删/重排），旧蒙皮对新骨架静默失效——网格挂上了但引擎画不出来；
- 人类腹部网格没事，因为人类的骨架改动无害（同样的代码、同样的流程，人类正常）；
- 我们已经试过数据层的 `NeedsSkeletonRemap=True` 标志（提交 778830a）——无效；
  也对照过游戏本体视觉条目的全部字段（`SkeletonResource` 等全空，与我们一致）——
  **没有可以抄的字段级捷径，必须重导出网格**。

好消息：**100 个腹部的形状（morph 步进）都不用重做**，只需要把它们从旧骨架
"换绑"到新骨架再导出。这是纯流程活，下面一步步来。

## 3. 方案 A（首选）：给现有 100 个网格"换骨"

思路：每个腹部 GR2 → 导入 Blender → 把网格重新绑定到新骨架 → 用**原文件名**导出回原位置。
形状、步进、UUID、材质、视觉库全部不动。

### 第 1 步：先做 1 个网格，验证流程

1. 打开 Blender（空场景）。
2. `File → Import → Divinity GR2`（或插件菜单里的 GR2 导入项），选工作目录里的
   `DGB_F_Base.GR2` → 场景里出现新骨架（一具骨架，无网格）。
3. **再**导入 `SP_DGB_F_Belly_1.GR2`（mod 目录里的）→ 出现旧骨架 + 肚子网格。
   此时旧骨架是它自带的（老骨骼）。
4. **骨骼名兼容性检查**（决定走 A 还是 B 的岔路口）：
   - 选中肚子网格 → 属性面板 `Object Data Properties（绿色三角）→ Vertex Groups`，
     记下它用到哪些骨骼名（一般是几根脊柱/骨盆附近的骨头）。
   - 在新骨架（DGB_F_Base）的骨架模式里看这些**同名骨骼是否存在**。
   - **都存在** → 走 5a（运气好，5 分钟完事）。
   - **有缺失/改名** → 走第 4 步的权重移植（方案 B 预备）。
5a. **同名重绑**：
   - 选肚子网格 → 加 `Armature` 修改器 → Object 选新骨架（DGB_F_Base）。
   - 删除旧的 Armature 修改器（指旧骨架那个）。
   - 摆个姿势测试：选中新骨架进 Pose 模式转一根脊柱骨——肚子应该跟着动。
5b. **名字对不上时的权重移植**（仍属方案 A 流程内，见第 4 步）。
6. **导出**：`File → Export → Divinity GR2`，目标 = **覆盖原文件**
   `...\Assets\Characters\Humans\SP_DGB_F_Belly_1.GR2`，文件名一个字符都不要改。
   导出设置保持插件默认（如询问骨架，选场景里的 DGB_F_Base）。
7. 肉眼复核：重新导入刚导出的文件，确认网格完整、顶点组正常。

### 第 2 步（如需）：权重移植（供体 = 当前身体网格）

如果第 1 步第 4 点发现旧骨骼名在新骨架里对不上：

1. 把当前身体网格 `DGB_F_NKD_Body_A.GR2` 也导入场景（它自带新骨架绑定）。
2. 选肚子网格 → 加 `Data Transfer` 修改器：
   - Source = 身体网格；勾 **Vert Data → Vertex Groups**；
   - Mapping = **Nearest Face Interpolated**（最近面插值）。
   - 肚子和身体是同一套拓扑区域，身体的新版蒙皮会"刷"到肚子上。
3. 应用（Apply）Data Transfer → 删除旧 Armature 修改器 → 加新的 Armature 修改器指新骨架。
4. 摆姿势确认肚子跟随腰部运动、没有大片撕裂。

> 每个肚子都要做一次。50 个文件手动做会疯掉——所以有了第 3 步的批量脚本。

### 第 3 步：批量跑剩下 99 个

第 1 步验证通过后，用脚本循环。Blender → `Scripting` 工作区，粘贴下面的脚本
（**先改开头的三个路径**）。它会：导入新骨架 → 逐个导入腹部 GR2 → 重绑
（同名骨骼直接绑；缺名的骨骼对身体的对应骨骼做权重移植）→ 覆盖导出。

```python
import bpy, os

# ===== 改这里 =====
NEW_SKELETON = r"<repo>\build\dgb-fix\DGB_F_Base.GR2"
DONOR_BODY   = r"<repo>\build\dgb-fix\DGB_F_NKD_Body_A.GR2"   # 骨骼名不匹配时才需要
BELLY_DIR    = r"<repo>\DevouringAndDigesting\Generated\Public\DevouringAndDigesting\Assets\Characters\Humans"
PREFIX       = "SP_DGB_F_Belly_"      # 改成 SP_DGB_M_Belly_ 换男性那批（骨架同时换 DGB_M_Base）
COUNT        = 50
# ==================

GR2_IMPORT  = "import_scene.dos2de_gr2"    # 若报错，在 Info 编辑器里看导入时的真实操作名
GR2_EXPORT  = "export_scene.dos2de_gr2"    # （不同插件版本可能是 dos2de_gr2 / gr2 等）

def clear():
    bpy.ops.object.select_all(action="SELECT")
    bpy.ops.object.delete()
    for block in (bpy.data.meshes, bpy.data.armatures, bpy.data.objects):
        for x in list(block):
            if x.users == 0: block.remove(x)

def import_gr2(path):
    before = set(bpy.data.objects)
    bpy.ops.import_scene.dos2de_gr2(filepath=path)   # ← 与 GR2_IMPORT 保持一致
    return [o for o in bpy.data.objects if o not in before]

clear()
skel = import_gr2(NEW_SKELETON)
new_arm = next(o for o in skel if o.type == 'ARMATURE')
new_bones = {b.name for b in new_arm.data.bones}

clear()
donor = import_gr2(DONOR_BODY)
donor_mesh = next((o for o in donor if o.type == 'MESH'), None)

report = []
for i in range(1, COUNT + 1):
    name = f"{PREFIX}{i}"
    src = os.path.join(BELLY_DIR, name + ".GR2")
    clear()
    arm = next((o for o in import_gr2(NEW_SKELETON) if o.type == 'ARMATURE'), None)
    objs = import_gr2(src)
    mesh = next(o for o in objs if o.type == 'MESH')
    old_arm = next((o for o in objs if o.type == 'ARMATURE'), None)

    # 删掉指向旧骨架的修改器，换绑新骨架；缺名骨骼从供体身体移植权重
    missing = [g.name for g in mesh.vertex_groups if g.name not in new_bones]
    for m in list(mesh.modifiers):
        if m.type == 'ARMATURE': mesh.modifiers.remove(m)
    if missing and donor_mesh:
        dt = mesh.modifiers.new("DT", 'DATA_TRANSFER')
        dt.object = donor_mesh; dt.use_vert_data = True
        dt.data_types_verts = {'VGROUP'}
        dt.vert_mapping = 'NEAREST_FACE_INTERPOLATED'
        bpy.context.view_layer.objects.active = mesh
        bpy.ops.object.modifier_apply(modifier=dt.name)
    m = mesh.modifiers.new("Armature", 'ARMATURE'); m.object = arm
    report.append((name, len(missing), missing[:4]))

    # 覆盖导出（保持原文件名！）
    bpy.ops.export_scene.dos2de_gr2(filepath=src)      # ← 与 GR2_EXPORT 保持一致

for name, nmiss, miss in report:
    print(f"{name}: missing {nmiss} bone groups {miss}")
```

注意事项：
- 两个 GR2 操作名以你装的插件版本为准（顶部两个常量）。跑**单个文件**先试，
  Blender 顶部 `Info` 日志里会显示真实操作名。
- 跑批前把整个 `Humans` 文件夹里的 `SP_DGB_*` 复制一份备份（git 已能还原，但本地备份更快）。
- 男性那批：把 `NEW_SKELETON` 换成 `DGB_M_Base.GR2`、`DONOR_BODY` 换成
  `DGB_M_NKD_Body_A.GR2`、`PREFIX` 换成 `SP_DGB_M_Belly_`，重跑一遍。
- 导出后 git 一看便知：100 个 GR2 变更、其它文件零改动 —— 这就是"改对了"的标志。

### 第 4 步：把重映射标志关掉

网格已经和当前骨架匹配后，`NeedsSkeletonRemap` 就不需要了（它本来也没救回来）：
在 `DevouringAndDigesting\Public\...\Content\Assets\Characters\Humans\[PAK]_Female_Belly\`
下的 `DGB_M_NKD_Body_A_Mesh.lsf.lsx`、`DGB_F_NKD_Body_A_Mesh.lsf.lsx` 里把所有
`NeedsSkeletonRemap` 的 `value="True"` 改回 `False`（两个文件各 50 处，全局替换即可）。

### 第 5 步：打包、安装、验证

1. 推送到 GitHub → Actions 构建出 pak（或本地用 lslib 打包）。
2. 装进 BG3 Mod Manager（覆盖旧的 DevouringAndDigesting.pak）。
3. 进游戏：龙裔角色喝口服药水 → 吞一个猎物。
4. 看控制台两行日志：
   - `Updating belly visual; Race: Dragonborn Sex: Male Belly: 8b7767e9-...`
   - `Visuals after override: ...`（确认 UUID 仍在列表里）
5. 肉眼：腹部随体积变大。**成了。**

### 常见坑

| 症状 | 原因 | 处理 |
|---|---|---|
| 导入 GR2 报错/空白 | divine.exe 路径没配 | 插件设置里指向 lslib 的 divine.exe |
| 导出后进游戏腹部位置漂移 | 导出时骨架选错/缩放不一致 | 新旧骨架应同原点同缩放；对照身体网格对齐 |
| 腹部显示但穿模/扭曲 | 个别骨骼名缺失没移植成功 | 看脚本打印的 missing 列表，对那几根骨用 Data Transfer |
| 还是完全不渲染 | 导出文件名变了/放错目录 | 核对 `SP_DGB_F_Belly_i.GR2` 原名原位 |
| 仅龙裔还是坏、人类也坏了 | 动了人类资产 | git 还原 Humans 目录，只保留 SP_DGB_* 变更 |

## 4. 方案 B（备选）：从 remeshed.blend 重新生成

仓库自带 `Blender/remeshed.blend`（腹部源网格 + `VORE` 形态键）和
`Blender/main.py`（按步进批量导出 + 生成视觉库 XML）。思路是：把 blend 里的
`Armature7`（DGB_F）/`Armature8`（DGB_M）替换成新骨架、重刷权重，再重跑 main.py。

**不推荐首选，原因有二：**
1. main.py 导出的是 DAE（`export_scene.dos2de_collada`），还要过一遍 lslib 转 GR2；
2. main.py 的 `write_one()` 每次都用 `uuid4()` 生成**新 UUID**——重新生成的视觉库
   XML 和 `Lua\Tables\BellyTable.lua` 里写死的 UUID、用户本地存档全都会失配。

如果走这条路：**只取它导出的网格，不要用它生成的 XML**（视觉库和 BellyTable.lua
保持现状），并在 main.py 里把 DGB 两项的 `Enabled` 改 True、其余保持 False。
方案 A 本质上是方案 B 的"只修绑骨、不重生成"变体，风险更小。

## 5. 一句话总结

代码无罪（探针已证明覆盖生效），数据字段无捷径（对照过游戏本体），
唯一路径 = 把 100 个 `SP_DGB_*_Belly_*.GR2` 在 Blender 里从旧龙裔骨架
换绑到 Patch 8 的 `DGB_F/M_Base` 骨架后**原名原位**导出——
文件名、UUID、材质、视觉库、BellyTable.lua 全都不用动。
